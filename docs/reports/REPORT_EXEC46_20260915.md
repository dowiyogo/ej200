## Output design and join

The existing `sipm_hits` tree was extended rather than creating a second tree. Every row already represents one accepted SiPM detection, so appending columns avoids a second large tree and a join during normal analysis. Existing column indices 0–11 were preserved. The join key for any derived table is `(event_id, track_id)`; `track_id` is unique only within an event, as defined by Geant4.

Appended branches are:

| Column | ROOT type | Definition |
|---|---:|---|
| `track_id` | `Int_t` | `G4Track::GetTrackID()` |
| `t_detection_ns` | `Double_t` | unsmeared physical global time at the detection step |
| `t_creation_ns` | `Double_t` | global minus local track time at detection |
| `x_creation_mm`, `y_creation_mm`, `z_creation_mm` | `Double_t` | `G4Track::GetVertexPosition()` |
| `wl_nm_created` | `Double_t` | wavelength derived from `GetVertexKineticEnergy()` |
| `path_length_mm` | `Double_t` | accumulated track length plus the current detection step |
| `exit_angle_deg` | `Double_t` | angle between pre-step momentum and outward SiPM-face normal |
| `n_boundary_encounters` | `Int_t` | completed `fGeomBoundary` steps originating in `BarLV`, excluding the final SiPM boundary |
| `source_type` | `Int_t` | existing classifier: 1 scintillation, 2 Cherenkov, 3 other, 0 primary |

`t_detection_ns` was added because legacy `time_ns` includes configurable electronic jitter. Using `time_ns` would invalidate the physical guard `t_detection >= t_creation` when nonzero jitter is selected and would contaminate the requested emission/propagation decomposition.

The boundary counter uses a `G4VUserTrackInformation` subclass. It is allocated lazily at the first non-SiPM bar boundary and is deleted with the Geant4 track. This gives O(1) lookup with no event-map hashing or explicit cleanup. Its cost is one small allocation for optical tracks that reach a counted boundary; an event-scoped map would avoid per-object allocation but add a hash lookup at every boundary and retain all entries until event end. Creation position, creation time, wavelength, and path length use native `G4Track` state and require no duplicated accumulator.

`BoundaryInvokeSD` runs before `G4SteppingManager` adds the current step to `G4Track::GetTrackLength()`. The recorded path therefore explicitly adds `step->GetStepLength()`; otherwise every detected track would be short by its final step.

A normalized source-spectrum test would require recording all created scintillation photons, which is unnecessary for the requested mechanism analysis.

## Mechanism readiness

| Mechanism | Classification after validation | Observable and limitation |
|---|---|---|
| (i) path/ray-angle dispersion | **Instrumented; not adjudicated** | `path_length_mm`, `n_boundary_encounters`, and `exit_angle_deg` show the expected center/near-end separation. A bare count does not retain the sequence or angle at every reflection. |
| (ii) wavelength-dependent velocity/filtering | **Instrumented; original difference variable is degenerate** | `wl_nm_created`, physical propagation time, and path support wavelength-conditioned group-velocity tests. With no wavelength-shifting process, `wl_nm - wl_nm_created` is identically zero; spectral filtering must be tested against the created/detected wavelength itself, not their difference. |
| (iii) PDE-weighted first-photon selection | **Instrumented; not adjudicated** | `(event_id,track_id)`, existing `pde`, face/sensor IDs, source type, and the event hit ensemble support first-versus-random selection and partial correlations. |
| (iv) scintillation emission-time order statistics | **Instrumented; not adjudicated** | `t_creation_ns` and raw `t_detection_ns` give `t_propagation = t_detection_ns - t_creation_ns` and allow left/right first-photon creation-time covariance. |
| shared event fluctuation prediction | **Testable; not adjudicated** | first left/right `t_creation_ns` can be correlated by event after production. |

Full separation may require more instrumentation only if path length, exit angle, wavelength, creation time, and boundary count leave an unresolved ray-history component. The next escalation would be a compact per-boundary angular/path summary or reflection timing, not a full hit history. It should be added only after the first full-grid analysis demonstrates that the current sufficient statistics fail.
